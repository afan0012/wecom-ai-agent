# 个人知识库导入与验收

## 先分清三类资料

| 目录 | 机器人会读取吗 | 应放什么 |
| --- | --- | --- |
| `knowledge/private/` | 不会 | 原始个人笔记、账号资料、行程、联系方式、未公开想法 |
| `knowledge/drafts/` | 不会 | 从 Obsidian、文本文件导入后等待审阅的内容 |
| `knowledge/approved/` | 会 | 已确认可以向外部客户和朋友回答的资料 |

不要把密钥、身份证件、聊天记录、精确地址、私人联系方式、未公开合作、账号 Cookie 或财务资料放进 `approved/`。

## 导入 Markdown / TXT

在项目根目录运行：

```powershell
python scripts\import_knowledge.py "D:\你的Obsidian库"
```

这只会复制 `.md` 和 `.txt` 到 `knowledge/drafts/`，不会自动公开。先阅读、删掉敏感段落，并确认内容可以对外说，再把单个文件移动到 `knowledge/approved/`。

建议在每份公开资料开头写：

```markdown
---
audience: public
source: 本人确认
updated: 2026-10-14
---
```

若 `audience` 不是 `public` 或 `external`，机器人不会读取它；这是防误放的第二道保险。

## 本次验收

1. 通过微信客服链接发送一句普通问题，确认仍能正常回复。
2. 单独发送一张带文字的截图；约 2.5 秒后，应收到图片内容概述或补充提问。
3. 发送“这张图是什么意思？”并紧接着发送图片；回答应结合图片，而不是只说收到图片。
4. 在 `knowledge/approved/` 放一份只含可公开信息的 Markdown，例如“我关注 AI 工具和短视频创作”；服务会自动刷新索引，再从微信询问相应问题，确认回答匹配资料。
5. 把一份测试资料留在 `knowledge/drafts/`，询问其中的独特词句；机器人不应引用它。

## 当前边界

- 这是轻量、可审计的 Markdown 检索，适合个人资料起步，不需要向量数据库。
- 图片可以在对话中由视觉模型理解，但图片文件本身还不会成为“按图检索”的知识库条目。
- 当资料量达到数千篇、需要 PDF/Word/表格批量解析或图片检索时，再把 `RAG_API_URL` 接到专业 RAG 平台。当前 2GB 服务器不适合直接部署 RAGFlow 或完整 Dify。
